One install, two ways to work

Most people start with one and end up using both, on the same daemon and memory.

Teams of agents start from a goal, schedule, webhook or GitHub event, and pause only where you ask for approval.

  • Review every pull request, fix labelled issues
  • Watch an inbox, draft calendar events
  • Research overnight, publish a report

Talk to it from Telegram, email or the web UI.

Example: a labelled GitHub issue starts a task; researcher, developer and reviewer agents fix it and open a pull request. A weekday schedule runs an inbox digest, asks for approval on the phone before sending an email, and delivers the summary to Telegram.
